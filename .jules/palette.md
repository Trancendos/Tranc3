## 2024-10-31 - Keyboard Accessible Interactions
**Learning:** Hidden components (like actions or icons) that appear on `group-hover` using `opacity-0` can be inaccessible to keyboard users if they do not appear gracefully when focused. Adding `group-focus-visible:opacity-100` alongside `group-hover:opacity-100` ensures that they are also shown when the user focuses on them. Also, a component with `onClick` but without semantic HTML elements (like `div`) needs a `role="button"` and a `tabIndex={0}` to be focusable via the keyboard, and an `onKeyDown` to handle keyboard events (Enter or Space) to make it accessible to keyboard users.
**Action:** When hiding secondary actions or icons using `opacity-0 group-hover:opacity-100`, always add `group-focus-within:opacity-100` (or `group-focus-visible`) and ensure the parent has interactive styles (e.g. `focus-visible:ring-2`) and keyboard handlers (`onKeyDown`) for non-semantic interactive elements. Add `aria-hidden="true"` to decorative inner icons to prevent redundant screen reader announcements. Add `aria-pressed` and `aria-disabled` as applicable to interactive components.
