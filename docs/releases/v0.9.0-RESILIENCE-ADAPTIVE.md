# TRANC3 v0.9.0 — Resilience & Adaptive Intelligence

**Status**: Planning / In Progress  
**Branch**: `feature/v0.9.0-resilience-adaptive`  
**Target Window**: 6–8 weeks  
**Theme**: Make TRANC3 more reliable to operate, more adaptive in its agents, and ready for stronger personality control — while staying true to zero-cost and self-hosted principles.

---

## 1. Release Objectives

1. Dramatically reduce operational friction (CI, backups, worker health).
2. Ship a working MVP of **hybrid agent orchestration** that **extends** the existing `AgentOrchestrator` + `AgentProfile` system (no parallel rewrite).
3. Lay clean foundations for **LoRA / QLoRA personality adapters** and DPO/ORPO training.
4. Clarify and partially improve the **hybrid database strategy** (SQLite + Postgres + NATS).

---

## 2. Scope

### P0 — Must Ship (Stabilisation)

| ID | Task | Owner Suggestion | Acceptance Criteria |
|----|------|------------------|---------------------|
| P0-1 | Fix CI reliability (flaky gates, CodeQL models, missing assets, supply-chain watch) | CI / Platform | Main stays green for ≥5 consecutive days; majority of open PRs unblocked |
| P0-2 | Automated backup + restore for SQLite DBs, Infinity Void, model weights | Ops / Reliability | Daily automated backups + documented successful restore drill |
| P0-3 | Basic self-healing (health checks + restart / circuit-break) | Platform | Failing workers auto-restart or isolated; alerts only escalate on persistent failure |
| P0-4 | Recommended Production Profile + resource guidance | Docs / Platform | Clear, tested `docker-compose` profile with CPU/RAM/GPU guidance |

### P1 — High Value (Adaptive Core)

| ID | Task | Owner Suggestion | Acceptance Criteria |
|----|------|------------------|---------------------|
| P1-1 | Hybrid Orchestration MVP (extends existing system) | Agents / Core | Accept/decline + short-lived helper roles + staleness re-plan work on top of current `AgentOrchestrator`; governance preserved |
| P1-2 | Improved multi-model / free-provider router | AI Gateway | Routing decisions logged; measurable improvement in fallback behaviour |
| P1-3 | First experimental trait adapters (QLoRA) | Model / Personality | ≥2 trait adapters trainable and loadable behind existing JSON profiles |

### P2 — Foundations

| ID | Task | Owner Suggestion | Acceptance Criteria |
|----|------|------------------|---------------------|
| P2-1 | Hybrid database strategy + migration helpers | Data / Platform | Written strategy + working migration path for shared state to Postgres |
| P2-2 | Complete high-volume queue move to NATS | Messaging | No remaining high-volume path still using SQLite queues |
| P2-3 | Basic agent reflection → personality proposal loop | Agents / Personality | Agents can propose refined profiles for human approval |

### Explicitly Out of Scope
- Full open-core decision
- Large model size increases
- Complete removal of all SQLite usage
- Major UI redesign
- Rewriting or replacing the existing `AgentOrchestrator` / `AgentProfile` system

---

## 3. Success Metrics

- Main branch CI remains green for consecutive days
- Successful automated restore of critical data demonstrated
- Hybrid behaviours (accept/decline, helper roles, staleness re-plan) function on the existing orchestrator
- At least two trait adapters can be trained and loaded
- Clear written hybrid database guidance exists
- No duplicate or competing agent orchestration layers introduced

## 5. Alignment Summary (Post-Review)

After reviewing the full `src/agents/` package:

- The existing system is already sophisticated (governance-aware task queue, rich specialist profiles, decomposition, memory, tool bridge).
- The v0.9.0 hybrid work therefore **extends** rather than replaces it.
- `src/agents/interfaces.py` provides clean abstract contracts for the new autonomy features; it is not a second orchestration engine.
- Documentation has been updated to remove any implication of a parallel rewrite.
